# 4편. OAuth 클라이언트와 애플리케이션

OAuth 클라이언트는 DataGSM 로그인을 쓰는 서비스의 등록 정보이고, 애플리케이션은 자기만의 권한 범위를 정의하는 서비스의 등록 정보입니다.

## 필요한 이유

### OAuth 클라이언트

아무 서비스나 DataGSM 로그인을 쓸 수 있으면 다음 문제가 생깁니다.

- 가짜 서비스가 DataGSM 로그인 화면을 띄워 사용자 정보를 가져갈 수 있습니다.
- 로그인 결과를 엉뚱한 주소로 보내게 만들 수 있습니다.
- 동의 화면에 어떤 서비스가 정보를 요청하는지 표시할 수 없습니다.

그래서 DataGSM 로그인을 쓰려면 먼저 OAuth 클라이언트로 등록해야 합니다. 등록할 때 서비스 이름, 로그인 후 돌아갈 주소, 요청할 권한을 정하고, DataGSM은 등록된 내용대로만 로그인을 처리합니다.

### 애플리케이션

DataGSM 기본 권한은 학생 정보 조회, 동아리 정보 조회처럼 DataGSM이 가진 데이터에 대한 권한입니다.

교내 서비스끼리 서로의 기능을 쓰려는 경우도 있습니다. 예를 들어 다른 서비스가 "급식 알리미"의 급식 평가 등록 기능을 쓰려면, 급식 알리미는 사용자가 그 권한을 허락했는지 확인할 수 있어야 합니다.

이때 애플리케이션을 씁니다. 급식 알리미가 애플리케이션을 만들고 `meal_write` 같은 권한 범위를 정의하면, 다른 서비스는 DataGSM 로그인으로 그 권한을 요청하고 사용자는 DataGSM 동의 화면에서 허락합니다. 기술 문서에서는 이 기능을 서드파티 권한 범위라고 부릅니다.

## 사용자

| 누가 | 어디서 | 무엇을 |
|---|---|---|
| 외부 개발자 | 개발자 콘솔의 클라이언트 화면 | OAuth 클라이언트 등록, 수정, 삭제 |
| 외부 개발자 | 개발자 콘솔의 애플리케이션 화면 | 애플리케이션과 권한 범위 등록, 수정, 삭제 |
| 관리자 | 개발자 콘솔 | 다른 사람의 클라이언트와 애플리케이션 수정, 삭제 |

## OAuth 클라이언트 기능

<img src="https://res.cloudinary.com/dthsnnmej/image/upload/v1793708283/themoment-blog/jvrpmks9jmt97b85v13p.png" width="483" alt="이미지" />

### 클라이언트 등록

개발자 콘솔의 클라이언트 화면에서 만듭니다.

| 항목 | 설명 |
|---|---|
| 클라이언트 이름 | 개발자가 구분하기 위한 이름 |
| 서비스 명칭 | 로그인 페이지와 동의 화면에 표시되는 이름 (예: 급식 알리미) |
| 리다이렉트 URL | 로그인이 끝난 뒤 돌아갈 주소. 여러 개 등록할 수 있습니다. |
| 권한 범위 | 이 서비스가 사용자에게 요청할 수 있는 권한 목록. 최소 하나를 골라야 합니다. |

로그인 결과는 등록된 리다이렉트 URL로만 보냅니다. 로그인 결과를 다른 주소로 빼돌리는 공격을 막기 위해서입니다.

### 클라이언트 ID와 클라이언트 시크릿

클라이언트를 만들면 두 값을 받습니다.

- 클라이언트 ID: 서비스를 구분하는 값입니다. 공개되어도 됩니다.
- 클라이언트 시크릿: 서비스를 인증하는 비밀 값입니다. 공개하면 안 됩니다.

클라이언트 시크릿은 만들 때 한 번만 표시됩니다. DataGSM은 원래 값을 저장하지 않기 때문에 창을 닫으면 다시 확인할 수 없습니다. 화면에도 "반드시 복사하여 안전한 곳에 보관하세요"라는 경고가 나옵니다.

### 고를 수 있는 권한 범위

클라이언트에 고를 수 있는 권한 범위는 DataGSM에 등록된 모든 애플리케이션의 권한 범위입니다. DataGSM 기본 권한도 여기에 포함됩니다.

| DataGSM 기본 권한 | 뜻 |
|---|---|
| 계정 정보 조회 | 로그인한 사용자의 이메일, 권한 등급, 학생인지 선생님인지 |
| 학생 정보 조회 | 로그인한 사용자의 학생(또는 선생님) 정보 |
| 동아리 정보 조회 | 로그인한 사용자의 소속 동아리 |
| 프로젝트 정보 조회 | 로그인한 사용자가 참여한 프로젝트 |

동아리 정보 조회와 프로젝트 정보 조회는 클라이언트에 등록해 두어도, 로그인 요청에 명시해야 받을 수 있습니다.

DataGSM도 내부적으로 "DataGSM"이라는 애플리케이션으로 등록되어 있고, 위 권한은 그 애플리케이션의 권한 범위입니다. 그래서 DataGSM 기본 권한과 다른 서비스가 만든 권한은 같은 방식으로 처리됩니다.

### 클라이언트 수정과 삭제

클라이언트 이름, 서비스 명칭, 리다이렉트 URL은 수정할 수 있습니다. 권한 범위는 수정할 수 없으므로 바꾸려면 클라이언트를 새로 만들어야 합니다. 클라이언트를 삭제하면 그 서비스는 DataGSM 로그인을 쓸 수 없습니다.

수정과 삭제는 만든 사람과 관리자만 할 수 있습니다.

## 애플리케이션 기능

<img src="https://res.cloudinary.com/dthsnnmej/image/upload/v1793708310/themoment-blog/xbcfdbd4zabfhdvojoin.png" width="477" alt="이미지" />

### 애플리케이션 등록

개발자 콘솔의 애플리케이션 화면에서 이름과 권한 범위 목록을 입력해 만듭니다. 권한 범위마다 이름과 설명을 적습니다.

| 항목 | 예시 | 규칙 |
|---|---|---|
| 권한 이름 | `meal_read` | 영어 소문자, 숫자, `_`, `-`만 쓸 수 있습니다. 한 애플리케이션 안에서 중복될 수 없습니다. |
| 권한 설명 | 급식 평가 조회 | 동의 화면에 표시되는 설명입니다. 필수입니다. |

애플리케이션을 만들면 애플리케이션 ID가 생깁니다. 실제 권한 범위는 `애플리케이션ID:권한이름` 형식이라, 서로 다른 애플리케이션이 같은 권한 이름(예: `read`)을 써도 구분됩니다.

### 권한 범위 추가, 수정, 삭제

만든 뒤에도 권한 범위를 추가하거나, 이름과 설명을 고치거나, 삭제할 수 있습니다.

권한 범위를 삭제하면 그 권한을 고른 모든 클라이언트에서도 빠집니다. 애플리케이션을 삭제하면 그 애플리케이션의 권한 범위가 모두 클라이언트에서 빠집니다.

수정과 삭제는 만든 사람과 관리자만 할 수 있습니다.

### 애플리케이션 권한이 쓰이는 과정

1. 급식 알리미 개발자가 애플리케이션을 만들고 `meal_write`(급식 평가 등록) 권한을 정의합니다.
2. 다른 서비스 개발자가 OAuth 클라이언트를 만들 때 `meal_write` 권한을 고릅니다.
3. 사용자가 다른 서비스에서 DataGSM으로 로그인하면 동의 화면에 "급식 평가 등록" 권한이 나오고, 사용자가 허락합니다.
4. 다른 서비스는 이 권한이 담긴 토큰을 받습니다.
5. 다른 서비스가 그 토큰으로 급식 알리미에 요청하면, 급식 알리미는 토큰이 DataGSM에서 발급된 것인지와 `meal_write` 권한이 있는지 확인하고 요청을 처리합니다.

## 비교

| 구분 | OAuth 클라이언트 | 애플리케이션 |
|---|---|---|
| 역할 | DataGSM 로그인을 쓰는 서비스 | 다른 서비스에 권한을 제공하는 서비스 |
| 발급되는 값 | 클라이언트 ID, 클라이언트 시크릿 | 애플리케이션 ID |
| 등록하는 내용 | 서비스 이름, 리다이렉트 URL, 요청할 권한 | 제공할 권한의 이름과 설명 |
| 필요한 경우 | DataGSM 로그인을 연동할 때 | 내 서비스의 기능을 다른 서비스에 권한으로 열어 줄 때 |

로그인만 연동하는 서비스는 OAuth 클라이언트만 만들면 됩니다.

## 다른 도메인과의 관계

- 계정 (1편): 클라이언트와 애플리케이션은 만든 계정에 속하고, 탈퇴하면 함께 삭제됩니다.
- 로그인 (2편): 로그인 페이지와 동의 화면에 나오는 서비스 이름과 권한 목록은 클라이언트에 등록한 값입니다.
- API 키 (3편): API 키 권한 범위(`student:read` 등)와 OAuth 권한 범위는 별개입니다. API 키는 데이터 전체 조회에, OAuth 권한은 로그인한 사용자의 허락이 필요한 조회에 씁니다.

## 용어

| 용어 | 뜻 |
|---|---|
| OAuth 클라이언트 | DataGSM 로그인을 쓰는 서비스의 등록 정보 |
| 클라이언트 ID | 클라이언트를 구분하는 공개 값 |
| 클라이언트 시크릿 | 클라이언트를 인증하는 비밀 값. 만들 때 한 번만 표시됩니다. |
| 리다이렉트 URL | 로그인이 끝난 뒤 돌아갈 주소 |
| 애플리케이션 | 자기만의 권한 범위를 정의하는 서비스의 등록 정보 |
| 서드파티 권한 범위 | 외부 애플리케이션이 정의한 권한. `애플리케이션ID:권한이름` 형식입니다. |
