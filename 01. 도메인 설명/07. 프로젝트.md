# 7편. 프로젝트 (Project)

> 우리 학교 학생들이 만든 프로젝트를 모아 두는 **아카이브**예요. 누가, 언제, 어떤 기술로, 무엇을 만들었는지 한곳에서 볼 수 있어요.

## 왜 필요한가요?

우리 학교 학생들은 토이 프로젝트, 팀 프로젝트, 동아리 프로젝트, 아이디어페스티벌까지 정말 많은 프로젝트를 만들어요. 그런데 이 프로젝트들은 대부분 흩어져서 사라져요.

- 졸업한 선배가 어떤 서비스를 만들었는지 찾기 어려워요.
- 교내에서 운영 중인 서비스가 무엇인지 한눈에 보기 어려워요.
- 학생 입장에서는 내가 만든 프로젝트를 정리해 둘 곳이 마땅치 않아요.

DataGSM의 프로젝트 기능은 이런 프로젝트들을 **공식 기록으로 남기고 누구나 볼 수 있게** 해요. 학생에게는 포트폴리오가 되고, 후배에게는 참고 자료가 돼요.

## 누가 쓰나요?

| 누가 | 어디서 | 무엇을 |
|---|---|---|
| 누구나 | 프로젝트 사이트 | 등록된 프로젝트 둘러보기 (로그인 없이) |
| 학생 | 프로젝트 사이트의 내 프로젝트 화면 | 프로젝트 등록 신청, 수정 신청, 신청 결과 확인 |
| 관리자 | 관리자 페이지의 프로젝트 관리, 프로젝트 신청 화면 | 신청 수락·거절, 프로젝트 직접 등록·수정·종료·삭제 |
| 외부 개발자 | OpenAPI | 프로젝트 정보 조회 (`project:read` 권한) |

| 아이콘 | 프로젝트를 나타내는 이미지 |

## 기능 살펴보기

### 프로젝트 둘러보기

프로젝트 사이트에서는 **로그인하지 않아도** 등록된 프로젝트 목록과 상세 정보를 볼 수 있어요. 다음 조건으로 찾아볼 수 있어요.

- 프로젝트 이름 검색
- 동아리
- 운영 상태 (운영 중, 종료)
- 카테고리

여기에 보이는 프로젝트는 관리자가 확인하고 수락한 **공식 프로젝트**뿐이에요.

### 프로젝트 등록 신청

학생은 프로젝트 사이트의 **내 프로젝트** 화면에서 프로젝트 등록을 신청해요. 이 화면은 학생 계정으로 로그인해야 쓸 수 있어요.

신청서에는 위의 프로젝트 정보를 채워요. 참여자는 재학생 중에서 골라요. 동명이인을 구분할 수 있도록 학번, 이름, 학과가 함께 보여요. 신청하는 학생 본인은 자동으로 참여자에 들어가요.

신청하면 바로 공개되지 않고 **신청 대기** 상태가 돼요. 관리자가 수락해야 공식 프로젝트로 등록돼요. 잘못된 정보나 장난 신청이 그대로 공개되는 걸 막기 위해서예요.

### 신청 수락과 거절

관리자 페이지의 **프로젝트 신청** 화면에서 들어온 신청을 확인해요. 신청마다 신규 등록인지, 기존 프로젝트의 수정인지 표시돼요.

- **수락**: 신청 내용이 공식 프로젝트 데이터에 반영돼요. 신규 신청이면 프로젝트가 새로 만들어지고, 수정 신청이면 기존 프로젝트가 바뀌어요.
- **거절**: **거절 사유**를 꼭 적어야 해요. 기존 프로젝트 데이터는 바뀌지 않아요.

학생은 내 프로젝트 화면에서 신청 상태(신청 대기, 수락, 거절)와 거절 사유를 볼 수 있어요. 거절된 신규 신청은 내용을 고쳐서 다시 신청할 수 있어요.

### 프로젝트 수정 신청

이미 등록된 프로젝트를 고치고 싶을 때도 신청을 해요. 프로젝트의 **신청자나 참여자**만 수정 신청을 할 수 있어요.

수정 신청도 관리자가 수락해야 반영돼요. 한 프로젝트에는 수정 신청이 하나만 있어서, 아직 처리되지 않은 상태에서 다시 신청하면 이전 신청 내용이 새 내용으로 바뀌어요.

### 아이콘 업로드

프로젝트 아이콘은 신청서에서 이미지 파일을 올려서 정해요. 너무 많이 올리는 걸 막기 위해 아이콘 업로드는 **1분에 10번**까지만 할 수 있어요.

### 관리자의 프로젝트 관리

관리자는 신청을 거치지 않고 관리자 페이지에서 프로젝트를 직접 다룰 수 있어요.

- **등록, 수정**: 프로젝트를 바로 만들거나 고쳐요.
- **종료**: 운영이 끝난 프로젝트를 "종료" 상태로 바꾸고 종료 연도를 적어요. 종료 연도는 시작 연도보다 앞설 수 없어요.
- **운영 재개**: 종료된 프로젝트를 다시 "운영 중"으로 바꿔요. 종료 연도는 지워져요.
- **삭제**: 프로젝트를 지워요.

종료와 삭제는 달라요. 종료는 "예전에 이런 프로젝트가 있었다"는 기록을 남기고, 삭제는 기록 자체를 지워요.

### OpenAPI로 프로젝트 정보 제공

외부 서비스는 `project:read` 권한이 있는 API 키로 프로젝트 정보를 조회할 수 있어요. 관리자 권한이 있는 API 키(`project:write`)로는 프로젝트를 등록하거나 고칠 수도 있어요.

## 다른 도메인과의 관계

- **학생 (5편)**: 신청자와 참여자는 학생이에요. 참여자는 재학생 중에서 골라요.
- **동아리 (6편)**: 동아리 프로젝트는 동아리에 속해요. 폐지된 동아리로는 새로 신청할 수 없어요.
- **로그인 (2편)**: 외부 서비스는 사용자의 동의를 받아 그 사용자가 참여한 프로젝트 목록을 받을 수 있어요.
- **이벤트 (9편)**: 프로젝트가 만들어지거나, 바뀌거나, 삭제되면 `project.updated` 이벤트로 외부 서비스에 알려요.

## 기억할 용어

| 용어 | 뜻 |
|---|---|
| 공식 프로젝트 | 관리자가 수락해서 공개된 프로젝트 |
| 신청 | 학생이 프로젝트 등록이나 수정을 요청하는 것 |
| 신청자 | 프로젝트를 처음 등록 신청한 학생 |
| 참여자 | 프로젝트를 함께 만든 학생 |
| 종료 | 프로젝트 기록은 남기고 운영만 끝난 상태로 바꾸는 것 |

## 한 번 더 정리

- 프로젝트 사이트에서 누구나 로그인 없이 우리 학교 프로젝트를 둘러볼 수 있어요.
- 학생이 등록이나 수정을 신청하면, 관리자가 수락해야 공식 프로젝트에 반영돼요.
- 거절할 때는 사유를 적고, 학생은 고쳐서 다시 신청할 수 있어요.
- 수정 신청은 신청자와 참여자만 할 수 있어요.
- 관리자는 프로젝트를 직접 등록, 수정, 종료, 재개, 삭제할 수 있어요.
