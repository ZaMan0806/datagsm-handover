# 1편. 계정 (Account)

> DataGSM을 쓰는 모든 사람의 "회원 정보"예요. 학교 구성원만 가입할 수 있게 막고, 사람마다 할 수 있는 일을 나눠요.

## 왜 필요한가요?

DataGSM은 학생 정보처럼 민감한 학교 데이터를 다뤄요. 아무나 가입해서 데이터를 가져가면 안 되겠죠.
그래서 DataGSM은 **학교 이메일(`@gsm.hs.kr`)을 가진 사람만** 가입할 수 있게 하고, 가입한 사람마다 **권한 등급**을 매겨서 할 수 있는 일을 나눠요.

계정은 DataGSM의 모든 기능이 출발하는 곳이에요. API 키, OAuth 클라이언트, 이벤트처럼 뒤에서 배울 기능은 전부 "어떤 계정이 만들었는지"와 함께 저장돼요.

## 누가 쓰나요?

| 누가 | 어디서 | 무엇을 |
|---|---|---|
| 학생, 선생님 | 로그인 페이지 | 회원가입, 비밀번호 재설정 |
| 로그인한 모든 사용자 | 개발자 콘솔의 내 정보 화면 | 내 정보 확인, 회원 탈퇴 |
| 관리자 | 관리자 페이지의 계정 관리, 선생님 승인 화면 | 계정 검색, 권한 변경, 선생님 가입 승인 |

## 기능 살펴보기

### 회원가입

회원가입은 **학생 가입**과 **선생님 가입** 두 가지가 있어요. 둘 다 이메일 인증을 거쳐요.

1. 학교 이메일을 입력하면 인증 코드가 메일로 와요. 코드는 **5분** 동안만 쓸 수 있어요.
2. 받은 코드를 입력해서 본인 이메일이 맞는지 확인해요.
3. 비밀번호를 정하면 가입이 끝나요.

`@gsm.hs.kr`이 아닌 이메일이나 이미 가입된 이메일로는 가입할 수 없어요.

**학생 가입**은 가입하자마자 바로 쓸 수 있어요. 이때 DataGSM은 같은 이메일을 가진 학생 정보를 학생 명부에서 찾아서 계정과 **자동으로 연결**해요. 그래서 학생은 학번이나 이름을 따로 입력하지 않아요. (학생 명부는 [5편](./05.%20학생.md)에서 다뤄요.)

**선생님 가입**은 이름과 소속 부서를 함께 입력해요. 소속 부서는 마이스터부, 사감선생님, 학년부, 교무부, 전문교육부, 취업진로부, 행정실 중에서 골라요. 선생님 계정은 바로 쓸 수 없고 **승인 대기** 상태로 만들어져요. 관리자가 승인해야 로그인할 수 있어요.

### 선생님 가입 승인

선생님 계정을 승인제로 둔 이유는 학생이 선생님인 척 가입하는 일을 막기 위해서예요.

관리자 페이지의 **선생님 승인** 화면에는 승인을 기다리는 선생님 목록이 나와요. 이름, 이메일, 소속 부서, 설명, 신청일을 보고 결정해요.

- **허락**: 계정이 활성 상태가 되고, 그때부터 로그인할 수 있어요.
- **거절**: 계정과 함께 입력한 선생님 정보가 **삭제돼요.** 되돌릴 수 없어요.

### 비밀번호 재설정

비밀번호를 잊었을 때 쓰는 기능이에요. 회원가입과 비슷하게 이메일 인증 코드로 진행해요.

1. 이메일을 입력하면 재설정 코드가 메일로 와요. 코드는 **5분** 동안 쓸 수 있어요.
2. 코드를 입력해서 확인해요.
3. 새 비밀번호를 정해요.

가입되지 않은 이메일을 입력해도 "없는 이메일이에요"라고 알려주지 않아요. 이렇게 하면 다른 사람이 어떤 이메일이 가입돼 있는지 알아낼 수 없어요.

### 시도 횟수 제한

인증 코드는 8자리 숫자라서, 아무 숫자나 계속 넣어 보면 언젠가 맞출 수 있어요. 이런 공격을 막으려고 DataGSM은 **같은 이메일로 짧은 시간에 너무 많이 시도하면 잠시 막아요.**

| 동작 | 허용 횟수 |
|---|---|
| 회원가입 인증 메일 보내기 | 10분에 5번 |
| 회원가입 인증 코드 확인 | 5분에 10번 |
| 비밀번호 재설정 메일 보내기 | 10분에 3번 |
| 비밀번호 재설정 코드 확인 | 10분에 5번 |
| 비밀번호 변경 | 60분에 3번 |
| 로그인 | 10분에 10번 |

### 권한 등급

모든 계정에는 세 가지 등급 중 하나가 붙어요. 관리자 페이지에서는 각각 **루트, 어드민, 유저**로 보여요.

| 등급 | 누구 | 할 수 있는 일 |
|---|---|---|
| 유저 (USER) | 가입한 모든 사람의 기본 등급 | 내 정보 관리, 읽기 전용 API 키 발급, OAuth 클라이언트·애플리케이션·이벤트 등록 |
| 어드민 (ADMIN) | 운영진 | 유저가 하는 일 전부 + 관리자 페이지 사용 (학생, 동아리, 프로젝트, 계정, API 키 관리) |
| 루트 (ROOT) | 최고 관리자 | 어드민과 같고, 다른 사람이 권한을 바꿀 수 없는 계정 |

### 계정 관리와 권한 변경

관리자 페이지의 **계정 관리** 화면에서는 가입한 모든 계정을 이메일, 권한, 상태로 찾아볼 수 있어요. 계정을 누르면 그 계정에 연결된 학생 정보나 선생님 정보도 함께 보여요.

여기서 관리자가 다른 계정의 권한을 바꿀 수 있어요. 다만 사고를 막기 위해 몇 가지가 막혀 있어요.

- 본인 계정의 권한은 바꿀 수 없어요.
- 루트 계정의 권한은 바꿀 수 없어요.
- 누구에게도 루트 권한을 줄 수 없어요.

### 내 정보와 회원 탈퇴

개발자 콘솔의 **내 정보** 화면에서는 내 계정 정보와 연결된 학생 정보(학번, 기숙사 호실, 동아리 등)를 볼 수 있어요. 학생이라면 여기서 진로와 GitHub 아이디도 고칠 수 있어요. 이 부분은 [5편](./05.%20학생.md)에서 다시 다뤄요.

**회원 탈퇴**는 비밀번호를 한 번 더 입력해야 진행돼요. 탈퇴하면 그 계정으로 만든 것들이 **모두 함께 삭제돼요.**

- API 키
- OAuth 클라이언트와 애플리케이션
- 이벤트
- 외부 서비스에 해 준 동의 기록
- 로그인 세션

탈퇴해도 학생 명부에 있는 학생 정보 자체는 남아요. 학생 명부는 계정과 별개로 학교가 관리하는 데이터이기 때문이에요.

## 다른 도메인과의 관계

- **학생, 선생님**: 계정은 "로그인할 수 있는 사람"이고, 학생 정보와 선생님 정보는 "그 사람이 누구인지"예요. 둘은 이메일로 연결돼요.
- **로그인 (2편)**: 여기서 만든 계정으로 DataGSM 로그인을 해요. 승인 대기 중인 선생님은 로그인할 수 없어요.
- **API 키 (3편)**: 권한 등급에 따라 받을 수 있는 API 키의 권한 범위가 달라요.
- **OpenAPI**: OpenAPI로 제공되는 학생 데이터에는 **DataGSM에 가입한 학생만** 포함돼요. 가입할 때 개인정보 처리약관에 동의한 학생의 데이터만 내보내기 때문이에요.

## 기억할 용어

| 용어 | 뜻 |
|---|---|
| 승인 대기 (PENDING) | 가입은 했지만 아직 쓸 수 없는 상태. 선생님 계정이 처음에 이 상태예요. |
| 활성 (ACTIVE) | 정상적으로 쓸 수 있는 상태 |
| 권한 등급 (Role) | 루트, 어드민, 유저. 계정이 할 수 있는 일의 범위 |
| 계정 연결 | 계정을 학생 정보나 선생님 정보와 이어 주는 것 |

## 한 번 더 정리

- 학교 이메일(`@gsm.hs.kr`)로만 가입할 수 있고, 이메일 인증 코드를 거쳐요.
- 학생은 바로 쓸 수 있고, 선생님은 관리자가 승인해야 쓸 수 있어요.
- 권한 등급은 루트, 어드민, 유저 세 가지예요. 어드민 이상만 관리자 페이지를 써요.
- 인증 코드와 로그인은 시도 횟수 제한이 있어요.
- 탈퇴하면 그 계정으로 만든 API 키, 클라이언트, 이벤트 등이 모두 삭제돼요.
