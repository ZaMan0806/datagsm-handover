# 9편. 이벤트 (Event, Webhook)

> 학생, 동아리, 프로젝트 정보가 바뀌면 DataGSM이 등록된 외부 서버로 변경 내용을 보내는 기능입니다.

## 필요한 이유

외부 서비스가 DataGSM 데이터의 변경을 알아내는 방법은 두 가지입니다.

| 방법 | 설명 | 단점 |
|---|---|---|
| 폴링 | 외부 서비스가 주기적으로 DataGSM에 데이터를 다시 요청합니다. | 바뀐 것이 없어도 요청이 계속 나가고, 요청 사이에 바뀐 내용은 늦게 반영됩니다. |
| 이벤트 (웹훅) | 데이터가 바뀌면 DataGSM이 외부 서버로 바로 알립니다. | 알림을 받을 서버 주소가 필요합니다. |

DataGSM 이벤트는 두 번째 방식입니다.

## 사용자

| 누가 | 어디서 | 무엇을 |
|---|---|---|
| 외부 개발자 | 개발자 콘솔의 이벤트 화면 | 수신 URL과 구독할 이벤트 등록, 수정, 삭제 |
| 외부 개발자의 서버 | 자기 서버 | DataGSM이 보낸 알림 수신, 처리 |

## 기능

### 지원하는 이벤트

| 이벤트 | 전송 시점 |
|---|---|
| `student.updated` | 학생 정보가 바뀔 때 (수정, 졸업, 자퇴, 학생 구분 변경, 정보 수정 요청 등) |
| `club.updated` | 동아리가 만들어지거나, 수정되거나, 삭제될 때 |
| `project.updated` | 프로젝트가 만들어지거나, 수정되거나, 삭제될 때 |

세 이벤트 모두 바뀌기 전(old) 정보와 바뀐 후(new) 정보를 함께 보냅니다. 생성, 수정, 삭제는 이벤트 이름이 아니라 두 값을 비교해서 구분합니다. 예를 들어 old가 비어 있으면 새로 만들어진 것입니다.

엑셀 업로드처럼 여러 건이 한 번에 바뀌면 한 알림에 모아서 보냅니다.

### 이벤트 등록

개발자 콘솔의 이벤트 화면에서 두 가지를 정해 등록합니다.

- 수신 URL: 알림을 받을 서버 주소입니다. `http://`나 `https://`로 시작해야 합니다.
- 구독 이벤트: 받을 이벤트를 하나 이상 고릅니다.

계정마다 최대 10개까지 등록할 수 있고, 10개가 되면 추가 버튼이 비활성화됩니다.

등록한 뒤에도 수신 URL과 구독 이벤트를 수정하거나 이벤트를 삭제할 수 있습니다.

### 서명용 secret

이벤트를 등록하면 secret 값을 받습니다. secret은 등록할 때 한 번만 표시됩니다.

수신 URL은 인터넷에 열려 있어서 다른 사람이 DataGSM을 사칭해 요청을 보낼 수 있습니다. 그래서 DataGSM은 알림마다 secret으로 만든 서명을 함께 보내고, 받는 서버는 자기가 가진 secret으로 서명을 확인합니다. 확인 방법은 기술 문서의 서명 검증 가이드에 있습니다.

### 주소 검증

이벤트를 등록하거나 수신 URL을 바꾸면 DataGSM이 그 주소를 검증합니다.

| 상태 | 뜻 |
|---|---|
| 검증 대기 중 | 확인 중입니다. |
| 검증 완료 | 알림을 보낼 수 있습니다. |
| 검증 실패 | 알림을 보낼 수 없는 주소입니다. |

`localhost`, 내부망(사설 IP) 주소, 존재하지 않는 주소는 검증에 실패합니다. 이벤트 기능을 이용해 DataGSM 내부망에 요청을 보내는 공격을 막기 위해서입니다.

알림은 검증 완료된 이벤트에만 보냅니다. 검증에 실패하면 수신 URL을 고쳐서 다시 검증받아야 합니다.

### 전송과 재시도

정보가 바뀌면 구독 중인 모든 수신 URL로 알림을 보냅니다. 전송은 비동기로 처리되어 관리자의 작업 속도에 영향을 주지 않습니다.

받는 서버가 응답하지 않으면 최대 3번까지 시도합니다. 두 번째 시도는 1초 뒤, 세 번째 시도는 10초 뒤입니다.

3번 모두 실패한 알림은 다시 보내지 않습니다. 받는 쪽에서는 주기적으로 OpenAPI로 전체 데이터를 받아 맞춰 보는 것을 권장합니다.

## 다른 도메인과의 관계

- 학생, 동아리, 프로젝트 (5~7편): 이 세 정보가 바뀔 때 이벤트를 보냅니다. 관리자 페이지, OpenAPI, 로그인 중 정보 수정 등 어디서 바뀌어도 전송됩니다.
- NEIS (8편): NEIS 데이터는 이벤트를 보내지 않습니다.
- 계정 (1편): 이벤트는 만든 계정에 속하고, 탈퇴하면 함께 삭제됩니다.

## 용어

| 용어 | 뜻 |
|---|---|
| 웹훅 (Webhook) | 데이터가 바뀌면 상대 서버로 알림을 보내는 방식 |
| 폴링 (Polling) | 바뀐 것이 있는지 주기적으로 다시 요청하는 방식 |
| 수신 URL | 알림을 받을 서버 주소 |
| 구독 | 받을 이벤트를 골라 두는 것 |
| secret | 알림이 DataGSM에서 온 것인지 확인할 때 쓰는 비밀 값. 등록할 때 한 번만 표시됩니다. |
| 서명 | secret으로 만든 확인용 값. 알림마다 함께 보냅니다. |
| 재시도 | 전송에 실패했을 때 다시 보내는 것 |
