# 9편. 이벤트 (Event, Webhook)

> 학생, 동아리, 프로젝트 정보가 바뀌면 DataGSM이 **외부 서비스에 먼저 알려 주는** 기능입니다.

## 왜 필요합니까?

외부 서비스가 DataGSM의 학생 정보를 가져다 쓴다고 해 보겠습니다. 학생 정보는 언제든 바뀔 수 있습니다. 졸업하거나, 반이 바뀌거나, 동아리를 옮기기도 합니다.

외부 서비스가 바뀐 정보를 알아내는 방법은 두 가지입니다.

| 방법 | 설명 | 문제점 |
|---|---|---|
| **폴링** | 외부 서비스가 몇 분마다 "바뀐 것이 있습니까?" 하고 계속 물어봅니다. | 바뀐 게 없어도 계속 요청해서 낭비가 큽니다. 물어보는 사이에 바뀐 건 늦게 압니다. |
| **이벤트 (웹훅)** | 바뀌는 순간 DataGSM이 "이것이 바뀌었습니다" 하고 먼저 알려 줍니다. | 받을 서버 주소가 있어야 합니다. |

택배에 비유하면 폴링은 택배가 왔는지 계속 현관문을 열어 보는 것이고, 이벤트는 택배 기사님이 도착하면 초인종을 눌러 주는 것입니다.

DataGSM의 이벤트 기능은 두 번째 방법입니다. 외부 서비스는 DataGSM에 계속 물어보지 않아도 바뀐 내용을 바로 반영할 수 있습니다.

## 누가 사용합니까?

| 누가 | 어디서 | 무엇을 |
|---|---|---|
| 외부 개발자 | 개발자 콘솔의 이벤트 화면 | 받을 주소와 구독할 이벤트 등록, 수정, 삭제 |
| 외부 개발자의 서버 | 자기 서버 | DataGSM이 보낸 알림을 받아서 처리 |

## 기능 살펴보기

### 지원하는 이벤트

| 이벤트 | 언제 보냅니까? |
|---|---|
| `student.updated` | 학생 정보가 바뀔 때 (수정, 졸업, 자퇴, 학생 구분 변경, 정보 수정 요청 등) |
| `club.updated` | 동아리가 만들어지거나, 바뀌거나, 삭제될 때 |
| `project.updated` | 프로젝트가 만들어지거나, 바뀌거나, 삭제될 때 |

세 이벤트 모두 **바뀌기 전(old)** 정보와 **바뀐 후(new)** 정보를 함께 보냅니다. 만들어진 건지, 바뀐 건지, 삭제된 건지는 이벤트 이름이 아니라 이 두 값을 비교해서 알 수 있습니다. 예를 들어 바뀌기 전 정보가 비어 있으면 새로 만들어진 것입니다.

엑셀 업로드처럼 한 번에 여러 개가 바뀌면, 바뀐 것들을 모아서 한 번에 보냅니다.

### 이벤트 등록

개발자 콘솔의 **이벤트** 화면에서 등록합니다. 정하는 것은 두 가지입니다.

- **수신 URL**: 알림을 받을 내 서버 주소입니다. `http://`나 `https://`로 시작해야 합니다.
- **구독 이벤트**: 위 세 가지 중 받고 싶은 이벤트를 고릅니다. 최소 하나는 골라야 합니다.

계정 하나당 이벤트는 **최대 10개**까지 등록할 수 있습니다. 10개를 채우면 추가 버튼이 막힙니다.

등록한 뒤에도 수신 URL과 구독 이벤트를 바꾸거나, 이벤트를 삭제할 수 있습니다.

### 서명용 secret

이벤트를 등록하면 **secret**이라는 비밀 값을 받습니다. 이 값도 클라이언트 시크릿처럼 **등록할 때 딱 한 번만** 보여 줍니다.

secret은 "이 알림을 진짜 DataGSM이 보냈는지" 확인하는 데 씁니다. 수신 URL은 결국 인터넷에 열려 있는 주소라서, 누군가 DataGSM인 척 가짜 알림을 보낼 수 있기 때문입니다.

DataGSM은 알림을 보낼 때마다 secret으로 만든 **서명**을 함께 보냅니다. 받는 서버는 자기가 가진 secret으로 같은 계산을 해 보고, 서명이 맞으면 진짜 DataGSM이 보낸 알림이라고 믿을 수 있습니다. 서명을 확인하는 자세한 방법은 기술 문서의 서명 검증 가이드에 있습니다.

### 주소 검증

이벤트를 등록하거나 수신 URL을 바꾸면, DataGSM은 그 주소가 알림을 보내도 괜찮은 주소인지 **검증**합니다. 검증 상태는 세 가지입니다.

| 상태 | 뜻 |
|---|---|
| 검증 대기 중 | 아직 확인 중입니다. |
| 검증 완료 | 알림을 보낼 수 있습니다. |
| 검증 실패 | 알림을 보낼 수 없는 주소입니다. |

`localhost`나 내부망(사설 IP) 주소처럼 **외부에서 접근할 수 없는 주소**, 그리고 존재하지 않는 주소는 검증에 실패합니다. 누군가 이벤트 기능을 이용해서 DataGSM 서버 내부를 공격하는 일을 막기 위해서입니다.

알림은 **검증 완료**된 이벤트에만 보냅니다. 검증에 실패했다면 수신 URL을 바르게 고쳐서 다시 검증받아야 합니다.

### 전송과 재시도

정보가 바뀌면 DataGSM은 구독 중인 모든 수신 URL로 알림을 보냅니다. 이 전송은 **따로(비동기로)** 처리돼서, 알림을 보내는 동안 관리자의 작업이 느려지지 않습니다.

받는 서버가 응답하지 않으면 DataGSM은 잠시 뒤에 다시 보냅니다. **최대 3번**까지 시도하고, 다시 보낼 때마다 기다리는 시간이 길어집니다(1초 뒤, 10초 뒤).

3번 모두 실패하면 그 알림은 **다시 보내지 않습니다.** 그래서 받는 쪽에서는 알림만 믿지 말고, 가끔 OpenAPI로 전체 데이터를 다시 받아서 맞춰 보는 것이 좋습니다.

## 다른 도메인과의 관계

- **학생, 동아리, 프로젝트 (5~7편)**: 이 세 가지 정보가 바뀔 때 이벤트를 보냅니다. 관리자 페이지에서 바꾸든, OpenAPI로 바꾸든, 학생이 로그인하면서 정보를 고치든 모두 이벤트가 나갑니다.
- **NEIS (8편)**: NEIS 데이터는 이벤트를 보내지 않습니다.
- **계정 (1편)**: 이벤트는 만든 계정에 속하고, 탈퇴하면 함께 삭제됩니다.

## 기억할 용어

| 용어 | 뜻 |
|---|---|
| 웹훅 (Webhook) | 무언가 바뀌면 상대 서버에 먼저 알려 주는 방식 |
| 폴링 (Polling) | 바뀐 게 있는지 계속 물어보는 방식 |
| 수신 URL | 알림을 받을 서버 주소 |
| 구독 | 받고 싶은 이벤트를 골라 두는 것 |
| secret | 알림이 진짜인지 확인할 때 쓰는 비밀 값. 등록할 때 한 번만 보입니다. |
| 서명 | secret으로 만든 확인용 값. 알림마다 함께 보냅니다. |
| 재시도 | 전송에 실패했을 때 다시 보내는 것 |

## 한 번 더 정리

- 이벤트는 학생, 동아리, 프로젝트가 바뀌면 DataGSM이 외부 서버에 먼저 알려 주는 기능입니다.
- 알림에는 바뀌기 전과 바뀐 후 정보가 함께 들어 있습니다.
- 계정당 최대 10개까지 등록할 수 있고, secret은 등록할 때 한 번만 보입니다.
- 외부에서 접근할 수 없는 주소는 검증에 실패하고, 검증 완료된 이벤트에만 알림을 보냅니다.
- 최대 3번까지 보내고, 그래도 실패하면 그 알림은 사라집니다.
