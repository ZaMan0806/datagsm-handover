# 5편. 학생 (Student)

> 우리 학교 학생 전체의 **명부**예요. 교내 서비스들이 같은 학생 정보를 정확하게 쓸 수 있도록 DataGSM이 한곳에서 관리해요.

## 왜 필요한가요?

교내 서비스를 만들다 보면 학생 정보가 거의 항상 필요해요. 몇 학년 몇 반인지, 어느 학과인지, 기숙사 몇 호실인지 같은 정보요.

DataGSM이 없을 때는 서비스마다 학생 정보를 따로 모았어요. 그러다 보니 이런 문제가 생겼어요.

- 학생은 서비스마다 같은 정보를 반복해서 입력해야 해요.
- 서비스마다 정보가 달라요. 어떤 서비스는 작년 반 정보를 쓰고 있기도 해요.
- 새 학기마다 모든 서비스가 각자 학생 정보를 다시 정리해야 해요.

DataGSM은 학생 정보를 **한곳에서 정확하게 관리**하고, 다른 서비스는 그 정보를 가져다 쓰기만 하면 되게 해요. DataGSM이 다루는 학생 정보는 학년, 반, 기숙사 호실처럼 학교에서 이미 공개적으로 관리하는 정보예요.

## 누가 쓰나요?

| 누가 | 어디서 | 무엇을 |
|---|---|---|
| 관리자 | 관리자 페이지의 학생 관리 화면 | 학생 등록, 수정, 엑셀 업로드·다운로드, 졸업·자퇴 처리, 정보 수정 요청 |
| 학생 | 개발자 콘솔의 내 정보 화면 | 내 정보 확인, 진로와 GitHub 아이디 수정 |
| 학생 | 로그인 페이지 | 정보 수정 요청 받은 항목 입력 |
| 외부 개발자 | OpenAPI | 학생 정보 조회 (`student:read` 권한) |

## 학생 정보에는 무엇이 있나요?

| 항목 | 설명 |
|---|---|
| 이름, 이메일, 성별 | 기본 정보. 이메일은 학교 이메일이에요. |
| 학번 | 학년, 반, 번호 |
| 학과 | SW개발과, 스마트IoT과, 인공지능과 |
| 기숙사 호실 | 기숙사 방 번호 |
| 전공 동아리, 자율 동아리 | 소속 동아리 (6편에서 다뤄요) |
| 학생 구분 | 일반학생, 학생회, 기숙사자치위원회, 졸업생, 자퇴생 |
| 진로 | 프론트엔드, 백엔드, AI, 안드로이드 등 희망 진로 |
| GitHub 아이디 | 학생의 GitHub 계정 |

학생 정보는 계정과 별개로 존재해요. 관리자가 학생 정보를 먼저 등록해 두면, 학생이 나중에 같은 이메일로 가입할 때 계정과 학생 정보가 자동으로 연결돼요. ([1편](./01.%20계정.md) 참고)

## 기능 살펴보기

### 학생 조회와 검색

관리자 페이지의 학생 관리 화면에서 학생 목록을 표로 봐요. 다음 조건으로 걸러 볼 수 있어요.

- 학년, 반
- 성별
- 학생 구분 (학생회, 기숙사자치위원회 등)
- 이름 검색
- 졸업생이나 자퇴생 포함 여부

### 학생 등록과 수정

관리자는 학생을 한 명씩 추가하거나 정보를 고칠 수 있어요. 학생 구분만 바꾸면 상태만 바뀌고, 다른 정보를 바꾸면 그 정보가 수정돼요.

### 엑셀 다운로드와 업로드

학생이 수백 명이라 한 명씩 고치기는 힘들어요. 그래서 엑셀로 한 번에 다룰 수 있어요.

- **다운로드**: 지금 등록된 학생 정보를 엑셀 파일로 받아요.
- **업로드**: 고친 엑셀 파일을 올리면 학생 정보가 한 번에 바뀌어요.

엑셀 업로드는 **이미 등록된 학생의 정보를 한꺼번에 고치는 용도**예요. 엑셀의 학번으로 학생을 찾아서 고치기 때문에, 엑셀에 있는 학번과 DataGSM에 있는 학번이 정확히 같아야 해요. 학번이 빠지거나 겹치거나, 없는 동아리 이름이 들어 있으면 업로드가 거부돼요. 그래서 보통은 **다운로드한 파일을 고쳐서 다시 올리는** 방식으로 써요.

### 졸업과 자퇴 처리

학생이 졸업하거나 자퇴하면 학생 구분을 **졸업생**이나 **자퇴생**으로 바꿔요.

- **특정 학생 졸업 처리**: 한 명을 졸업생으로 바꿔요.
- **3학년 전체 졸업 처리**: 2월에 3학년 전체를 한 번에 졸업생으로 바꿔요.
- **특정 학생 자퇴 처리**: 한 명을 자퇴생으로 바꿔요.

졸업생이나 자퇴생이 되면 학번, 학과, 기숙사 호실, 소속 동아리가 **비워져요.** 더 이상 재학생이 아니니까요. 한 명씩 졸업이나 자퇴 처리를 하면 진로 정보와 동아리 부장 자리도 함께 비워져요. 학생 정보 자체는 지워지지 않아서, 졸업생도 DataGSM 계정은 그대로 쓸 수 있어요.

되돌릴 수 없는 작업이라 관리자 페이지에서 실행하기 전에 한 번 더 확인을 받아요.

### 정보 수정 요청

[2편](./02.%20로그인%20%28OAuth%29.md)에서 본 "정보 수정 요구"를 보내는 곳이 여기예요.

새 학기가 되면 학번, 기숙사 호실, 동아리가 바뀌는데, 관리자가 전부 직접 고치기는 어려워요. 그래서 학생 본인이 고치도록 요청을 보내요.

1. 관리자가 학생 관리 화면에서 대상 학생들을 골라요.
2. 다시 입력받을 항목을 골라요. 학번, 기숙사 호실, 전공 동아리, 자율 동아리 중에서 고를 수 있어요.
3. 요청을 보내면 고른 항목이 **바로 비워져요.** 틀린 옛날 정보가 남아 있는 것보다 비어 있는 게 낫기 때문이에요.
4. 학생은 다음에 DataGSM으로 로그인할 때 그 항목을 입력해야 로그인이 끝나요.

되돌릴 수 없는 작업이라 실행하기 전에 한 번 더 확인을 받아요.

### 학생 본인이 고칠 수 있는 정보

학생은 개발자 콘솔의 **내 정보** 화면에서 두 가지를 직접 고칠 수 있어요.

- **진로**: 목록에서 고르거나 직접 입력해요. 목록에는 프론트엔드, 백엔드, AI, 안드로이드, iOS, 플러터, IoT, 공기업·금융권, 클라우드·DevOps, PM·PO, 부사관, IT 엔지니어, 보안, 로보틱스, 게임개발이 있어요.
- **GitHub 아이디**: 등록하면 GitHub 프로필 링크로 보여요.

학번이나 동아리처럼 학교가 관리해야 하는 정보는 학생이 마음대로 바꿀 수 없어요. 관리자가 고치거나, 정보 수정 요청을 받았을 때만 입력할 수 있어요.

### OpenAPI로 학생 정보 제공

외부 서비스는 `student:read` 권한이 있는 API 키로 학생 정보를 조회할 수 있어요. ([3편](./03.%20API%20키.md) 참고)

이때 **DataGSM에 가입한 학생의 정보만** 제공해요. 가입하면서 개인정보 처리약관에 동의한 학생의 데이터만 외부에 내보내기 때문이에요.

관리자 권한이 있는 API 키(`student:write`)로는 OpenAPI에서 학생 정보를 등록하거나 고칠 수도 있어요.

## 다른 도메인과의 관계

- **계정 (1편)**: 같은 이메일로 학생 정보와 계정이 연결돼요.
- **로그인 (2편)**: 정보 수정 요청을 받은 학생은 로그인할 때 정보를 입력해요.
- **동아리 (6편)**: 학생은 전공 동아리와 자율 동아리에 하나씩 소속될 수 있어요. 동아리 부장도 학생이에요.
- **프로젝트 (7편)**: 프로젝트 참여자는 재학생 중에서 골라요.
- **이벤트 (9편)**: 학생 정보가 바뀌면(수정, 졸업, 자퇴, 정보 수정 요청 등) `student.updated` 이벤트로 외부 서비스에 알려요.

## 기억할 용어

| 용어 | 뜻 |
|---|---|
| 학생 명부 | DataGSM에 등록된 학생 정보 전체 |
| 학생 구분 | 일반학생, 학생회, 기숙사자치위원회, 졸업생, 자퇴생 |
| 학과 (major) | SW개발과, 스마트IoT과, 인공지능과 |
| 진로 (specialty) | 학생이 직접 정하는 희망 분야. 학과와 다른 거예요. |
| 정보 수정 요청 | 관리자가 고른 항목을 비우고, 학생이 로그인할 때 다시 입력하게 하는 기능 |

## 한 번 더 정리

- DataGSM은 학생 정보를 한곳에서 관리하고, 다른 서비스는 가져다 쓰기만 해요.
- 관리자는 학생을 한 명씩 또는 엑셀로 한꺼번에 관리해요. 엑셀 업로드는 기존 학생 정보를 고치는 용도예요.
- 졸업이나 자퇴를 하면 학번, 학과, 기숙사 호실, 동아리가 비워져요.
- 새 학기에는 정보 수정 요청으로 학생이 직접 정보를 고치게 할 수 있어요.
- OpenAPI로는 DataGSM에 가입한 학생의 정보만 제공해요.
