# 10편. 문서와 상태 페이지 (docs, status)

<img src="https://res.cloudinary.com/dthsnnmej/image/upload/v1793713963/themoment-blog/pvlgtkjxwflputgmiork.png" width="600" alt="이미지" />

기술 문서는 외부 개발자용 DataGSM 사용 설명서이고, 상태 페이지는 DataGSM 서버가 정상인지 보여 주는 페이지입니다.

## 필요한 이유

### 기술 문서

외부 개발자가 DataGSM을 쓰려면 다음 내용을 알아야 합니다.

- API 키를 넣어 요청하는 방법
- 응답 형식
- DataGSM 로그인을 연동하는 방법
- 이벤트 알림의 서명을 확인하는 방법

기술 문서에 이 내용을 정리해 두어, 개발자가 운영진에게 묻지 않고 찾아볼 수 있게 합니다.

### 상태 페이지

DataGSM에서 데이터를 받지 못할 때 원인이 내 서비스인지 DataGSM 서버인지 확인하는 데 씁니다.

## 사용자

| 누가 | 어디서 | 무엇을 |
|---|---|---|
| 외부 개발자 | 기술 문서 (`docs.datagsm.kr`) | OpenAPI, OAuth, 이벤트 사용법 확인 |
| 누구나 | 상태 페이지 | DataGSM 서버 상태 확인 |
| DataGSM 운영진 | 두 사이트 모두 | 문서 관리, 장애 확인 |

## 기술 문서

기술 문서는 Overview, OpenAPI, OAuth, Event 네 부분으로 나뉩니다.

### Overview

DataGSM 소개, 만들어진 배경과 역사, 제공 기능이 있습니다.

### OpenAPI

학교 데이터를 API로 조회하는 방법입니다.

- HTTP: 학생, 동아리, 프로젝트, NEIS(급식, 학사일정, 시간표) API의 요청과 응답 형식
- SDK: Java/Kotlin, Python, JavaScript/TypeScript, .NET, Go SDK 사용법. SDK를 쓰면 HTTP 요청을 직접 만들지 않고 함수 호출로 데이터를 받을 수 있습니다.
- SDK 버저닝 컨벤션: SDK 버전 번호 규칙

### OAuth

DataGSM 로그인을 연동하는 방법입니다.

- 기본 개념과 흐름: 로그인 순서와 토큰 설명
- PKCE 가이드
- 서드파티 권한 범위: 애플리케이션으로 권한 범위를 만드는 방법
- HTTP: 로그인 시작, 토큰 교환, 토큰 갱신, 사용자 정보 조회 요청
- Examples: React + Spring Boot, Next.js + Spring Boot, React + Spring Boot (Kotlin), Vanilla JS + NestJS 예제 코드
- SDK: React SDK, Java/Kotlin SDK
- Design 가이드: "DataGSM으로 로그인" 버튼 디자인 규칙

### Event

이벤트 알림을 받는 방법입니다.

- 이벤트 페이로드 명세: `student.updated`, `club.updated`, `project.updated` 알림의 내용
- 서명 검증 가이드: 알림이 DataGSM에서 온 것인지 확인하는 방법

### 로그인 버튼 디자인 가이드

서비스마다 "DataGSM으로 로그인" 버튼 모양이 같도록 공식 로고와 버튼 규칙을 제공합니다.

- 로고: Pixel Logo, Logotype
- 버튼: 글자가 있는 기본 버튼(높이 40px), 아이콘만 있는 아이콘 버튼(40px × 40px)
- 마우스를 올렸을 때(Hover)의 모양

문서에서 버튼 데모를 직접 눌러 볼 수 있습니다.

## 상태 페이지

### 확인하는 서버

| 서버 | 역할 |
|---|---|
| Web | 개발자 콘솔, 관리자 페이지, 프로젝트 사이트가 쓰는 서버 |
| OpenAPI | 학생, 동아리, 프로젝트, NEIS 데이터 API 서버 |
| OAuth Authorization | 로그인과 토큰 발급 서버 |
| OAuth Resource | 로그인한 사용자 정보를 제공하는 서버 |

서버가 기능별로 나뉘어 있어서 한 서버에 문제가 생겨도 다른 기능은 동작할 수 있습니다. 예를 들어 OpenAPI 서버가 멈춰도 로그인은 됩니다. 그래서 상태도 서버별로 표시합니다.

### 상태 표시

| 상태 | 뜻 |
|---|---|
| 정상 | 서버가 정상 동작 중입니다. |
| 배포 진행 중 | 새 버전으로 교체하는 중이라 잠시 쓸 수 없습니다. |
| 서비스 다운 | 서버에 문제가 있습니다. |

서버별 응답 시간도 표시됩니다. 상태는 30초마다 자동으로 다시 확인하고, 새로고침 버튼으로 바로 확인할 수도 있습니다.

## 다른 도메인과의 관계

- API 키, 학생, 동아리, 프로젝트, NEIS (3, 5~8편): 기술 문서의 OpenAPI 부분에서 사용법을 설명합니다.
- 로그인, OAuth 클라이언트와 애플리케이션 (2, 4편): 기술 문서의 OAuth 부분에서 사용법을 설명합니다.
- 이벤트 (9편): 기술 문서의 Event 부분에서 알림 형식과 서명 확인 방법을 설명합니다.

## 용어

| 용어 | 뜻 |
|---|---|
| 기술 문서 | 외부 개발자용 DataGSM 사용 설명서 |
| SDK | 특정 프로그래밍 언어에서 DataGSM API를 쉽게 호출하도록 만든 라이브러리 |
| 상태 페이지 | 서버가 정상인지 보여 주는 페이지 |
| 배포 | 새 버전의 프로그램을 서버에 올리는 것 |
