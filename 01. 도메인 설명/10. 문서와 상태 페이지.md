# 10편. 문서와 상태 페이지 (docs, status)

> **기술 문서**는 외부 개발자가 DataGSM을 쓰는 방법을 배우는 곳이고, **상태 페이지**는 DataGSM 서버가 지금 정상인지 누구나 확인하는 곳이에요.

앞의 1~9편이 DataGSM의 "기능"이었다면, 이번 편은 그 기능을 **잘 쓰고 믿을 수 있게** 도와주는 두 사이트예요.

## 왜 필요한가요?

### 기술 문서가 필요한 이유

DataGSM의 주요 사용자는 교내 서비스를 만드는 외부 개발자예요. 아무리 좋은 기능이 있어도, 쓰는 방법을 모르면 쓸 수 없어요.

- API 키를 어떻게 넣어서 요청하는지
- 응답이 어떤 모양으로 오는지
- DataGSM 로그인을 내 서비스에 어떻게 붙이는지
- 이벤트 알림이 진짜인지 어떻게 확인하는지

이런 내용을 개발자가 매번 운영진에게 물어보면 서로 힘들어요. 그래서 DataGSM은 **기술 문서**에 사용법을 정리해 두고, 누구나 스스로 찾아볼 수 있게 해요.

### 상태 페이지가 필요한 이유

내 서비스가 갑자기 DataGSM에서 데이터를 못 받아 온다면, 원인이 내 코드인지 DataGSM 서버인지 헷갈려요. **상태 페이지**에서 DataGSM 서버가 정상인지 바로 확인할 수 있으면, 원인을 빠르게 찾을 수 있어요.

## 누가 쓰나요?

| 누가 | 어디서 | 무엇을 |
|---|---|---|
| 외부 개발자 | 기술 문서 (`docs.datagsm.kr`) | OpenAPI, OAuth, 이벤트 사용법 확인 |
| 누구나 | 상태 페이지 | DataGSM 서버가 정상인지 확인 |
| DataGSM 운영진 | 두 사이트 모두 | 문서 관리, 장애 확인 |

## 기술 문서 살펴보기

기술 문서는 크게 네 부분으로 나뉘어요.

### Overview

DataGSM이 무엇인지, 왜 만들어졌는지, 어떤 기능을 제공하는지 소개해요. DataGSM의 역사도 여기에 있어요. 후배들이 프로젝트를 이해할 때도 꼭 한 번 읽어 보면 좋아요.

### OpenAPI

학교 데이터를 API로 가져가는 방법이에요.

- **HTTP**: 학생, 동아리, 프로젝트, NEIS(급식, 학사일정, 시간표) API를 어떻게 요청하고 응답이 어떻게 오는지 설명해요.
- **SDK**: 여러 프로그래밍 언어에서 바로 쓸 수 있는 라이브러리 안내예요. Java/Kotlin, Python, JavaScript/TypeScript, .NET, Go SDK가 있어요.
- **SDK 버저닝 컨벤션**: SDK 버전 번호를 어떻게 매기는지 설명해요.

SDK가 있으면 개발자는 HTTP 요청을 직접 만들지 않고, 함수 하나만 불러서 데이터를 받을 수 있어요.

### OAuth

DataGSM 로그인을 내 서비스에 붙이는 방법이에요.

- **기본 개념과 흐름**: 로그인이 어떤 순서로 진행되는지, 토큰은 무엇인지 설명해요.
- **PKCE 가이드**: 보안을 높이는 로그인 방식 안내예요.
- **서드파티 권한 범위**: 애플리케이션으로 자기만의 권한을 만드는 방법이에요. ([4편](./04.%20OAuth%20클라이언트와%20애플리케이션.md) 참고)
- **HTTP**: 로그인 시작, 토큰 교환, 토큰 갱신, 사용자 정보 조회 요청 방법이에요.
- **Examples**: 실제로 동작하는 예제 코드예요. React + Spring Boot, Next.js + Spring Boot, React + Spring Boot (Kotlin), Vanilla JS + NestJS 조합이 있어요.
- **SDK**: React SDK와 Java/Kotlin SDK 안내예요.
- **Design 가이드**: "DataGSM으로 로그인" 버튼 디자인 규칙이에요.

### Event

이벤트 알림을 받는 방법이에요. ([9편](./09.%20이벤트.md) 참고)

- **이벤트 페이로드 명세**: `student.updated`, `club.updated`, `project.updated` 알림에 어떤 내용이 들어 있는지 설명해요.
- **서명 검증 가이드**: 알림이 진짜 DataGSM이 보낸 것인지 확인하는 방법이에요.

### 로그인 버튼 디자인 가이드

서비스마다 "DataGSM으로 로그인" 버튼을 제각각 만들면, 사용자가 DataGSM 로그인인지 알아보기 어려워요. 그래서 기술 문서에서 **공식 로고와 버튼 규칙**을 제공해요.

- 로고 두 가지: **Pixel Logo**, **Logotype**
- 버튼 두 가지: 글자가 있는 **기본 버튼**(높이 40px), 아이콘만 있는 **아이콘 버튼**(40px × 40px)
- 마우스를 올렸을 때(Hover)의 모양

문서 안에서 버튼을 직접 눌러 볼 수 있는 데모도 있어요.

## 상태 페이지 살펴보기

### 확인하는 서버

상태 페이지는 DataGSM의 서버 네 개를 확인해요.

| 서버 | 하는 일 |
|---|---|
| Web | 개발자 콘솔, 관리자 페이지, 프로젝트 사이트가 쓰는 서버 |
| OpenAPI | 학생, 동아리, 프로젝트, NEIS 데이터 API 서버 |
| OAuth Authorization | 로그인과 토큰 발급 서버 |
| OAuth Resource | 로그인한 사용자 정보를 제공하는 서버 |

DataGSM이 기능마다 서버를 나눠 둔 덕분에, 한 서버에 문제가 생겨도 다른 기능은 계속 쓸 수 있어요. 예를 들어 OpenAPI 서버가 멈춰도 로그인은 될 수 있어요. 상태 페이지에서 어느 서버에 문제가 있는지 따로 보여 주는 이유예요.

### 상태 표시

| 상태 | 뜻 |
|---|---|
| 정상 | 서버가 잘 동작하고 있어요. |
| 배포 진행 중 | 새 버전으로 바꾸는 중이라 잠시 쓸 수 없어요. 곧 돌아와요. |
| 서비스 다운 | 서버에 문제가 있어요. |

서버마다 응답 시간도 함께 보여요. 상태는 **30초마다** 자동으로 새로 확인하고, 새로고침 버튼으로 바로 다시 확인할 수도 있어요.

## 다른 도메인과의 관계

- **API 키, NEIS, 학생, 동아리, 프로젝트 (3, 5~8편)**: 기술 문서의 OpenAPI 부분에서 사용법을 설명해요.
- **로그인, OAuth 클라이언트와 애플리케이션 (2, 4편)**: 기술 문서의 OAuth 부분에서 사용법을 설명해요.
- **이벤트 (9편)**: 기술 문서의 Event 부분에서 알림 형식과 서명 확인 방법을 설명해요.

## 기억할 용어

| 용어 | 뜻 |
|---|---|
| 기술 문서 | 외부 개발자를 위한 DataGSM 사용 설명서 |
| SDK | 특정 프로그래밍 언어에서 DataGSM을 쉽게 쓰도록 만든 라이브러리 |
| 상태 페이지 | 서버가 정상인지 보여 주는 페이지 |
| 배포 | 새 버전의 프로그램을 서버에 올리는 것 |

## 한 번 더 정리

- 기술 문서에는 OpenAPI, OAuth, 이벤트의 사용법과 예제, SDK 안내가 있어요.
- "DataGSM으로 로그인" 버튼은 기술 문서의 디자인 가이드를 따라 만들어요.
- 상태 페이지는 서버 네 개의 상태를 30초마다 확인해서 보여 줘요.
- 기능마다 서버가 나뉘어 있어서, 한 서버에 문제가 생겨도 다른 기능은 계속 쓸 수 있어요.

## 시리즈를 마치며

1편부터 10편까지 DataGSM의 기능을 모두 살펴봤어요. 마지막으로 전체를 한 문장씩 정리해 볼게요.

| 편 | 한 문장 정리 |
|---|---|
| 1. 계정 | 학교 이메일로 가입하고, 권한 등급으로 할 수 있는 일을 나눠요. |
| 2. 로그인 | 교내 서비스용 "DataGSM으로 로그인"이에요. |
| 3. API 키 | 학교 데이터를 가져갈 때 쓰는 열쇠예요. |
| 4. 클라이언트와 애플리케이션 | 로그인을 쓰는 서비스와 권한을 제공하는 서비스의 등록증이에요. |
| 5. 학생 | 학교 전체 학생 명부예요. |
| 6. 동아리 | 동아리 목록과 구성원 정보예요. |
| 7. 프로젝트 | 학생 프로젝트 아카이브예요. |
| 8. NEIS | 급식, 학사일정, 시간표를 정리해서 제공해요. |
| 9. 이벤트 | 정보가 바뀌면 외부 서비스에 먼저 알려 줘요. |
| 10. 문서와 상태 페이지 | 사용법을 알려 주고, 서버 상태를 보여 줘요. |
