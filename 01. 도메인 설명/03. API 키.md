# 3편. API 키 (Auth)

OpenAPI로 학교 데이터를 조회할 때 요청과 함께 보내는 키입니다. 키마다 접근할 수 있는 데이터(권한 범위)가 정해져 있습니다.

## 필요한 이유

OpenAPI는 학생, 동아리, 프로젝트, 급식 같은 학교 데이터를 외부 서비스에 제공합니다. 키 없이 열어 두면 다음 문제가 생깁니다.

- 누가 데이터를 가져가는지 알 수 없습니다.
- 학교 구성원이 아닌 사람도 학생 정보를 가져갈 수 있습니다.
- 요청이 몰리면 서버가 느려지거나 멈춥니다.

그래서 OpenAPI를 쓰려면 API 키를 발급받아 요청마다 함께 보내야 합니다. DataGSM은 이 키로 요청한 사람과 권한, 요청 횟수를 확인합니다.

| 구분 | API 키 | OAuth 로그인 |
|---|---|---|
| 목적 | 학교 데이터 전체 조회 (예: 오늘 급식, 동아리 목록) | 로그인한 사용자 본인의 정보 조회 |
| 사용자 로그인 | 필요 없음 | 필요함 |
| 예시 | 급식 메뉴를 보여 주는 디스코드 봇 | "DataGSM으로 로그인"이 있는 교내 커뮤니티 |

## 사용자

| 누가 | 어디서 | 무엇을 |
|---|---|---|
| 로그인한 모든 사용자 | 개발자 콘솔 첫 화면 | 내 API 키 발급, 확인, 갱신, 삭제 |
| 관리자 | 관리자 페이지의 API 키 관리 화면 | 전체 API 키 검색, 삭제, 만료일 연장 |

### API 키 발급

개발자 콘솔 첫 화면에서 발급합니다. 발급할 때 두 가지를 정합니다.

- 권한 범위: 이 키로 접근할 데이터
- 설명: 키의 용도

API 키는 계정마다 하나만 가질 수 있습니다. 키가 이미 있으면 기존 키를 갱신하거나 삭제해야 합니다.

키는 요청 헤더 `X-API-KEY`에 넣어 보냅니다.

### 권한 범위

권한 범위 이름은 `데이터 종류:할 수 있는 일` 형식입니다.

| 권한 범위 | 뜻 | 받을 수 있는 사람 |
|---|---|---|
| `student:read` | 학생 데이터 조회 | 모든 사용자 |
| `club:read` | 동아리 데이터 조회 | 모든 사용자 |
| `project:read` | 프로젝트 데이터 조회 | 모든 사용자 |
| `neis:read` | 급식, 학사일정, 시간표 조회 | 모든 사용자 |
| `student:write` | 학생 데이터 생성, 수정, 삭제 | 관리자 |
| `club:write` | 동아리 데이터 생성, 수정, 삭제 | 관리자 |
| `project:write` | 프로젝트 데이터 생성, 수정, 삭제 | 관리자 |
| `student:*`, `club:*`, `project:*`, `neis:*` | 해당 데이터의 모든 권한 | 관리자 |

일반 사용자는 읽기 권한만, 관리자는 쓰기 권한까지 받을 수 있습니다. 발급 화면에는 내 등급에서 고를 수 있는 권한만 나옵니다.

필요한 권한만 고르는 것을 권장합니다. 급식만 쓰는 서비스라면 `neis:read` 하나로 충분하고, 키가 유출돼도 피해 범위가 줄어듭니다.

### 마스킹

전체 키 값은 발급하거나 새 키로 바뀔 때만 화면에 나옵니다. 그 뒤에는 일부를 가린 값만 보이므로, 키를 받으면 바로 따로 저장해 두어야 합니다.

### 만료와 갱신

API 키에는 만료일이 있습니다.

| 등급 | 유효 기간 |
|---|---|
| 일반 사용자 | 30일 |
| 관리자 | 365일 |

만료 전에 갱신하면 유효 기간이 다시 늘어납니다. 갱신하면서 권한 범위나 설명을 바꿀 수도 있습니다.

- 권한 범위와 설명을 그대로 두고 갱신: 같은 키를 계속 쓰고 기간만 늘어납니다.
- 권한 범위나 설명을 바꿔서 갱신: 기존 키는 폐기되고 새 키가 발급됩니다.

만료 후 15일까지는 갱신할 수 있습니다. 15일이 지난 키는 매일 새벽 3시에 자동으로 삭제되고, 이후에는 새로 발급받아야 합니다.

### 로테이션

키가 유출됐다고 의심될 때 씁니다. 기존 키를 폐기하고 권한 범위와 설명이 같은 새 키를 발급합니다. 기존 키는 바로 쓸 수 없게 됩니다.

### 요청량 제한

API 키 하나로 1분에 100번까지 요청할 수 있고, 넘으면 잠시 거절됩니다.

API를 쓰는 쪽에서는 받은 데이터를 저장해 두고 다시 쓰는(캐싱) 것을 권장합니다. 예를 들어 급식은 하루에 한 번 조회하면 됩니다.

### 관리자의 API 키 관리

관리자 페이지에서 전체 사용자의 API 키를 봅니다. 키 값은 가려서 표시됩니다.

- 검색: 키 ID, 계정, 권한 범위, 만료 여부, 갱신 가능 여부로 검색합니다.
- 삭제: 특정 키를 삭제합니다.
- 만료일 연장: 특정 키의 만료일을 오늘부터 지정한 일수 뒤로 정합니다. 만료 후 15일이 지난 키는 연장할 수 없습니다.

## 다른 도메인과의 관계

- 계정 (1편): API 키는 계정마다 하나입니다. 계정 등급에 따라 받을 수 있는 권한 범위와 유효 기간이 다르고, 탈퇴하면 키도 삭제됩니다.
- 학생, 동아리, 프로젝트, NEIS (5~8편): API 키로 조회하는 데이터입니다.
- OAuth 클라이언트 (4편): API 키는 데이터 조회용, OAuth 클라이언트는 로그인 연동용입니다.

## 용어

| 용어 | 뜻 |
|---|---|
| API 키 | OpenAPI를 호출할 때 요청한 사람을 확인하는 키 |
| 권한 범위 (scope) | 키로 접근할 수 있는 데이터의 범위. `student:read` 형식입니다. |
| 마스킹 | 키의 일부를 가려서 표시하는 것 |
| 갱신 | 키의 만료일을 다시 늘리는 것 |
| 로테이션 | 기존 키를 폐기하고 같은 설정의 새 키로 바꾸는 것 |
| 요청량 제한 (Rate Limit) | 일정 시간 동안 보낼 수 있는 요청 수의 상한 |
