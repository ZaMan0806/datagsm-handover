# 3편. API 키 (Auth)

> 외부 개발자가 DataGSM의 학교 데이터를 가져갈 때 쓰는 **열쇠**입니다. 열쇠마다 열 수 있는 문(권한 범위)이 정해져 있습니다.

## 왜 필요합니까?

DataGSM의 OpenAPI는 학생, 동아리, 프로젝트, 급식 같은 학교 데이터를 외부 서비스에 제공합니다. 그런데 아무나 요청할 수 있게 열어 두면 문제가 생깁니다.

- 누가 데이터를 가져가는지 알 수 없습니다.
- 학교 구성원이 아닌 사람도 학생 정보를 가져갈 수 있습니다.
- 누군가 요청을 엄청나게 많이 보내면 서버가 느려지거나 멈춥니다.

그래서 OpenAPI를 쓰려면 **API 키**를 받아서, 요청할 때마다 함께 보내야 합니다. DataGSM은 API 키를 보고 "누가, 어떤 데이터를, 얼마나 자주" 요청하는지 확인합니다.

[2편](./02.%20로그인%20%28OAuth%29.md)의 로그인과 헷갈릴 수 있는데, 둘은 쓰임이 다릅니다.

| 구분 | API 키 | OAuth 로그인 |
|---|---|---|
| 목적 | 서비스가 **학교 데이터 전체**를 가져감 (예: 오늘 급식, 동아리 목록) | 서비스가 **로그인한 사용자 본인** 정보를 가져감 |
| 사용자 로그인 | 필요 없음 | 필요함 |
| 예시 | 급식 메뉴를 보여 주는 디스코드 봇 | "DataGSM으로 로그인"이 있는 교내 커뮤니티 |

## 누가 사용합니까?

| 누가 | 어디서 | 무엇을 |
|---|---|---|
| 로그인한 모든 사용자 | 개발자 콘솔 첫 화면 | 내 API 키 발급, 확인, 갱신, 삭제 |
| 관리자 | 관리자 페이지의 API 키 관리 화면 | 전체 API 키 검색, 삭제, 만료일 연장 |

## 기능 살펴보기

### API 키 발급

개발자 콘솔 첫 화면에서 API 키를 발급받습니다. 발급할 때 정하는 것은 두 가지입니다.

- **권한 범위**: 이 키로 어떤 데이터에 접근할지 고릅니다.
- **설명**: 이 키를 어디에 쓰는지 적습니다. 나중에 키를 관리할 때 도움이 됩니다.

API 키는 **계정 하나당 하나**만 가질 수 있습니다. 이미 키가 있으면 새로 발급하지 않고 기존 키를 갱신하거나 삭제해야 합니다.

발급된 키는 `X-API-KEY`라는 요청 헤더에 넣어서 보냅니다.

### 권한 범위

권한 범위는 "이 열쇠로 어떤 문을 열 수 있는지"입니다. 이름은 `데이터 종류:할 수 있는 일` 모양입니다.

| 권한 범위 | 뜻 | 받을 수 있는 사람 |
|---|---|---|
| `student:read` | 학생 데이터 조회 | 모든 사용자 |
| `club:read` | 동아리 데이터 조회 | 모든 사용자 |
| `project:read` | 프로젝트 데이터 조회 | 모든 사용자 |
| `neis:read` | 급식, 학사일정, 시간표 조회 | 모든 사용자 |
| `student:write` | 학생 데이터 생성, 수정, 삭제 | 관리자 |
| `club:write` | 동아리 데이터 생성, 수정, 삭제 | 관리자 |
| `project:write` | 프로젝트 데이터 생성, 수정, 삭제 | 관리자 |
| `student:*`, `club:*`, `project:*`, `neis:*` | 해당 데이터의 모든 권한 | 관리자 |

일반 사용자는 **읽기 권한만** 받을 수 있습니다. 데이터를 바꾸는 쓰기 권한은 관리자만 받을 수 있습니다. 발급 화면에도 내 등급에서 고를 수 있는 권한만 보입니다.

키를 발급할 때는 **필요한 권한만 고르는 것**이 좋습니다. 급식만 보여 줄 서비스라면 `neis:read` 하나면 충분합니다. 이렇게 하면 키가 유출되더라도 피해를 줄일 수 있습니다.

### 키 보안: 마스킹

전체 키 값은 **발급하거나 새 키로 바뀐 순간에만** 화면에 보입니다. 그 뒤로는 키의 일부를 가린(마스킹한) 값만 보입니다. 그래서 키를 받으면 바로 안전한 곳에 복사해 둬야 합니다.

### 만료와 갱신

API 키는 영원히 쓸 수 없고 **만료일**이 있습니다. 오래된 키가 어딘가에 유출된 채로 계속 쓰이는 일을 막기 위해서입니다.

| 등급 | 유효 기간 |
|---|---|
| 일반 사용자 | 30일 |
| 관리자 | 365일 |

만료가 가까워지면 **갱신**해서 기간을 다시 늘립니다. 갱신할 때 권한 범위나 설명을 함께 바꿀 수도 있습니다.

- 권한 범위와 설명을 그대로 두고 갱신하면: **같은 키**를 그대로 쓰면서 기간만 늘어납니다.
- 권한 범위나 설명을 바꿔서 갱신하면: 기존 키는 폐기되고 **새 키**가 발급됩니다.

키가 만료된 뒤에도 **15일 동안은** 갱신할 수 있습니다. 15일이 지나면 더 이상 갱신할 수 없고, 매일 새벽 3시에 자동으로 삭제됩니다. 그 뒤에는 새로 발급받아야 합니다.

### 로테이션

**로테이션**은 키가 유출됐다고 의심될 때 쓰는 기능입니다. 기존 키를 폐기하고, 권한 범위와 설명이 같은 **새 키**를 발급합니다. 유출된 키는 그 순간부터 쓸 수 없습니다.

### 요청량 제한

API 키 하나로는 **1분에 100번**까지 요청할 수 있습니다. 이보다 많이 요청하면 잠시 요청이 거절됩니다. 한 서비스가 요청을 너무 많이 보내서 다른 서비스까지 느려지는 일을 막기 위해서입니다.

그래서 API를 쓰는 쪽에서는 받은 데이터를 잠시 저장해 두고(캐싱) 다시 쓰는 것이 좋습니다. 예를 들어 급식은 하루에 한 번만 가져와도 충분합니다.

### 관리자의 API 키 관리

관리자 페이지에서는 모든 사용자의 API 키를 볼 수 있습니다. 키 값은 여기서도 가려서 보입니다.

- **검색**: 키 ID, 계정, 권한 범위, 만료 여부, 갱신 가능 여부로 찾습니다.
- **삭제**: 문제가 있는 키를 강제로 삭제합니다.
- **만료일 연장**: 특정 키의 만료일을 오늘부터 원하는 일수만큼 뒤로 정합니다. 갱신 가능 기간(만료 후 15일)이 지난 키는 연장할 수 없습니다.

## 다른 도메인과의 관계

- **계정 (1편)**: API 키는 계정마다 하나입니다. 계정 등급에 따라 받을 수 있는 권한 범위와 유효 기간이 다릅니다. 탈퇴하면 키도 삭제됩니다.
- **학생, 동아리, 프로젝트, NEIS (5~8편)**: API 키로 가져오는 데이터입니다.
- **OAuth 클라이언트 (4편)**: API 키는 "데이터 가져오기", OAuth 클라이언트는 "로그인 붙이기"용입니다.

## 기억할 용어

| 용어 | 뜻 |
|---|---|
| API 키 | OpenAPI를 호출할 때 누가 요청했는지 증명하는 열쇠 |
| 권한 범위 (scope) | 키로 접근할 수 있는 데이터의 범위. `student:read`처럼 씁니다. |
| 마스킹 | 키의 일부를 가려서 보여 주는 것 |
| 갱신 | 키의 만료일을 다시 늘리는 것 |
| 로테이션 | 기존 키를 폐기하고 같은 설정의 새 키로 바꾸는 것 |
| 요청량 제한 (Rate Limit) | 일정 시간 동안 보낼 수 있는 요청 수의 상한 |

## 한 번 더 정리

- API 키는 OpenAPI로 학교 데이터를 가져갈 때 쓰는 열쇠이고, 계정마다 하나입니다.
- 일반 사용자는 읽기 권한만, 관리자는 쓰기 권한까지 받을 수 있습니다.
- 일반 사용자 키는 30일, 관리자 키는 365일 동안 쓸 수 있고, 만료 후 15일 안에 갱신해야 합니다.
- 유출이 의심되면 로테이션으로 새 키를 받습니다.
- 키 하나로 1분에 100번까지 요청할 수 있습니다.
